# 功能規格：LSTM 台股價格預測系統

**功能分支**: `001-lstm-stock-prediction`
**建立日期**: 2025-11-15
**狀態**: 草稿
**輸入**: 使用者描述："LSTM 台股預測模型：預測未來 20 個交易日的漲跌幅區間及其信心度"

## 使用者情境與測試 *(必填)*

### 使用者情境 1 - 訓練基準模型並評估準確度 (優先級: P1)

資料科學家需要使用歷史台股資料訓練一個基準 LSTM 模型，並評估其預測未來 20 個交易日漲跌幅區間的準確度。

**為什麼這是優先級 P1**: 基準模型是整個預測系統的核心基礎，必須先建立並驗證可行性，才能進行後續的超參數調整與優化。這是最小可行產品 (MVP) 的核心功能。

**獨立測試**: 可以透過載入歷史資料、執行訓練腳本、獲得驗證損失與準確度指標來完全獨立測試。即使不進行超參數調整，此功能仍能提供有價值的預測模型。

**驗收場景**:

1. **Given** 歷史台股資料檔案 (包含開盤價、收盤價、成交量、技術指標、法人籌碼等)，**When** 執行資料預處理與特徵工程，**Then** 系統成功產生訓練資料集與驗證資料集，目標變數為 5 個類別的 One-Hot 編碼
2. **Given** 已預處理的訓練資料，**When** 使用基準模型配置 (3 層 Stacked LSTM: 128-64-32 單元，Dropout 0.2，學習率 0.001) 進行訓練，**Then** 模型成功訓練並在驗證集上產生驗證損失與分類準確度指標
3. **Given** 訓練完成的基準模型，**When** 使用測試資料進行預測，**Then** 系統輸出 5 維機率向量，並正確識別最高機率的漲跌幅區間類別

---

### 使用者情境 2 - 自動超參數調整尋找最佳模型 (優先級: P2)

資料科學家需要使用自動超參數調整工具 (Keras Tuner 或 Optuna) 系統性地探索不同參數組合，以找到驗證損失最小的最佳模型配置。

**為什麼這是優先級 P2**: 在基準模型驗證可行後，超參數調整可進一步提升模型效能。此功能獨立於基準模型，可在 P1 完成後單獨開發與測試。

**獨立測試**: 可以透過配置超參數搜尋空間、執行調整程序、並驗證是否正確記錄所有試驗結果與選定最佳模型來獨立測試。

**驗收場景**:

1. **Given** 預處理完成的訓練與驗證資料，**When** 配置超參數搜尋空間 (時間窗口: 20/40/60/80 天，LSTM 層數: 2/3/4 層，單元數: 32/64/128，Dropout: 0.1-0.4，學習率: 0.001/0.0005/0.0001，批次大小: 32/64/128，特徵集選擇: Set A/B/C)，**Then** 系統成功啟動超參數調整程序
2. **Given** 超參數調整正在執行，**When** 每個試驗 (Trial) 完成訓練，**Then** 系統自動記錄該試驗的參數組合、訓練歷史、最終驗證損失與準確度
3. **Given** 所有超參數試驗完成，**When** 系統比較所有試驗結果，**Then** 系統選定驗證損失最小的模型配置，並僅儲存該最佳模型檔案 (.h5 或 SavedModel 格式)
4. **Given** 超參數調整完成，**When** 使用者查詢調整歷史，**Then** 系統提供完整的試驗紀錄 (可透過 Keras Tuner / Optuna / MLflow 介面查詢)

---

### 使用者情境 3 - 根據指定日期預測未來收盤價 (優先級: P3)

使用者需要選擇特定日期，並獲得該日期後 20 個交易日的預測收盤價與實際收盤價 (如有歷史資料)。

**為什麼這是優先級 P3**: 此功能提供使用者友善的預測介面，但依賴於 P1 的模型訓練。可在模型訓練完成後獨立開發。

**獨立測試**: 可以透過提供測試日期、執行預測腳本、並驗證輸出格式與準確性來獨立測試。

**驗收場景**:

1. **Given** 已訓練完成的最佳模型，**When** 使用者指定某個日期 (例如 2024-01-15)，**Then** 系統載入該日期前 60 天的歷史資料作為輸入
2. **Given** 輸入資料已準備，**When** 模型執行預測，**Then** 系統輸出預測的漲跌幅區間 (0-4) 與信心度 (最高機率值)
3. **Given** 預測區間與信心度，**When** 系統計算預測的收盤價區間，**Then** 系統顯示預測收盤價範圍 (例如：預測 20 日後收盤價區間為 15,200 - 16,000 元，信心度 75%)
4. **Given** 指定日期後 20 個交易日存在於歷史資料中，**When** 系統查詢實際收盤價，**Then** 系統同時顯示實際收盤價與預測收盤價進行比較
5. **Given** 指定日期後 20 個交易日超過歷史資料範圍，**When** 系統嘗試查詢實際收盤價，**Then** 系統顯示 "N/A"

---

### 邊界案例

- **資料不足**: 當指定日期前的歷史資料少於 60 天時，系統應如何處理？
- **資料缺失**: 如果歷史資料中存在缺失值 (例如停牌日)，系統應如何填補或處理？
- **類別不平衡**: 如果訓練資料中某些漲跌幅類別樣本極少，系統應如何處理類別不平衡問題？
- **GPU 不可用**: 如果訓練環境的 GPU 無法使用，系統應自動降級使用 CPU 訓練還是中止並提示使用者？
- **超參數調整時間過長**: 如果超參數調整預計需要數天時間，系統是否支援中斷與恢復？

## 需求 *(必填)*

### 功能需求

- **FR-001**: 系統 **必須 (MUST)** 能夠從專案根目錄載入 `19980601-20251111-converted.csv` 檔案，該檔案包含以下欄位：date (日期)、open (開盤價)、high (最高價)、low (最低價)、close (收盤價)、volume (成交量)、移動平均線 (SMA5/10/20/60/120/240, MA5/10)、技術指標 (DIF12-26, MACD9, OSC, K(9,3), D(9,3))、法人籌碼 (net buy sell 淨買賣超、cumulative net buy sell 累積淨買賣超、buy 買超、sell 賣超)
- **FR-002**: 系統 **必須 (MUST)** 執行以下特徵工程：
  - 將價格類特徵 (open, high, low, close) 轉換為日報酬率
  - 納入所有技術指標 (DIF12-26, MACD9, OSC, K(9,3), D(9,3))
  - 納入法人籌碼 (net buy sell, cumulative net buy sell)，並考慮使用籌碼的變化率
  - 處理移動平均線特徵以反映長期動能，採用長短期 MA 的差距或斜率 (例如 SMA20/SMA60 的比值，或 SMA20 的每日斜率)
  - 對所有輸入特徵使用 MinMaxScaler 或 StandardScaler 進行標準化
- **FR-003**: 系統 **必須 (MUST)** 根據未來 20 日報酬率 R_{t→t+20} 計算目標變數，並將其轉換為 5 個類別的 One-Hot 編碼向量，類別閾值為：
  - 0 (極度下跌): R < -5.0%
  - 1 (溫和下跌): -5.0% ≤ R < -2.5%
  - 2 (區間震盪): -2.5% ≤ R ≤ +2.5%
  - 3 (溫和上漲): +2.5% < R ≤ +5.0%
  - 4 (極度上漲): R > +5.0%
- **FR-004**: 系統 **必須 (MUST)** 使用 60 天時間窗口作為預設輸入 (可在超參數調整時探索 20/40/60/80 天)
- **FR-005**: 系統 **必須 (MUST)** 建立 3 層 Stacked LSTM 模型作為基準配置 (128-64-32 單元)，並在各層之間加入 Dropout (0.2)
- **FR-006**: 系統 **必須 (MUST)** 使用 Categorical Cross-Entropy 損失函數與 Adam 優化器 (學習率 0.001)
- **FR-007**: 系統 **必須 (MUST)** 使用 Early Stopping 監控驗證損失，Patience 設定為 10 個 epoch
- **FR-008**: 系統 **必須 (MUST)** 準備三組不同的特徵集 (Set A, Set B, Set C)，每組包含不同的特徵組合策略，以供超參數調整時選擇最佳特徵集：
  - **Set A (動能型)**: 專注於中期趨勢與動能，包含價格變化率、Volume 變化率、SMA 比例、MACD (DIF12-26, MACD9)、法人籌碼 (排除 K(9,3), D(9,3), OSC 等震盪指標)
  - **Set B (震盪型)**: 專注於超買超賣反轉訊號，包含價格變化率、Volume 變化率、SMA 比例、K(9,3)、D(9,3)、法人籌碼 (排除 MACD 等趨勢指標)
  - **Set C (全特徵集)**: 包含所有處理過的特徵，整合動能與震盪指標
- **FR-009**: 系統 **必須 (MUST)** 支援使用 Keras Tuner 或 Optuna 進行自動超參數調整，搜尋空間包含：
  - 時間窗口 (Time Steps): {20, 40, 60, 80} 天
  - LSTM 層數: {2, 3, 4} 層
  - 每層單元數: {32, 64, 128}
  - Dropout 比率: [0.1, 0.4]
  - 學習率: {0.001, 0.0005, 0.0001}
  - 批次大小: {32, 64, 128}
  - 特徵集選擇 (Feature Set ID): {Set A, Set B, Set C}
- **FR-010**: 系統 **必須 (MUST)** 在超參數調整過程中僅儲存驗證損失最小的單一最佳模型檔案，該模型為所有超參數組合 (包含時間窗口、層數、學習率、特徵集 ID) 中的最佳配置
- **FR-011**: 系統 **必須 (MUST)** 使用 Keras Tuner / Optuna / MLflow 完整記錄所有試驗的參數組合 (包含特徵集 ID)、驗證指標與訓練日誌
- **FR-012**: 使用者 **必須能夠 (MUST be able to)** 指定特定日期並獲得該日期後 20 個交易日的預測漲跌幅區間與信心度
- **FR-013**: 系統 **必須 (MUST)** 在預測輸出中顯示預測的收盤價區間與實際收盤價 (如存在於歷史資料中)，若超過歷史資料範圍則顯示 "N/A"
- **FR-014**: 系統 **必須 (MUST)** 使用 GPU 進行訓練 (WSL2 + NVIDIA GPU 環境)，並在訓練日誌中記錄 GPU 使用狀態與記憶體資訊
- **FR-015**: 系統 **必須 (MUST)** 在 GPU 不可用時包含自動降級機制或明確錯誤提示

### 關鍵實體 *(如果功能涉及資料則包含此節)*

- **歷史股價資料 (Historical Stock Data)**: CSV 格式檔案 (`19980601-20251111-converted.csv`)，涵蓋 1998/6/1 至 2025/11/11，包含 date、OHLC (open/high/low/close)、volume、移動平均線 (SMA5/10/20/60/120/240, MA5/10)、技術指標 (DIF12-26, MACD9, OSC, K(9,3), D(9,3))、法人籌碼 (net buy sell, cumulative net buy sell, buy, sell) 等共 23 個欄位
- **特徵集 (Feature Set)**: 三組不同的特徵組合策略，用於超參數調整時比較特徵工程策略的效果
  - Set A (動能型): 趨勢動能特徵 (價格變化率、Volume 變化率、SMA 比例、MACD、法人籌碼)
  - Set B (震盪型): 反轉訊號特徵 (價格變化率、Volume 變化率、SMA 比例、K(9,3)、D(9,3)、法人籌碼)
  - Set C (全特徵集): 所有處理過的特徵
- **預處理資料集 (Preprocessed Dataset)**: 經過特徵工程與標準化後的訓練/驗證/測試資料集，根據選定的特徵集包含對應的輸入特徵序列 (形狀: [樣本數, 時間窗口, 特徵數]) 與目標變數 (形狀: [樣本數, 5])
- **LSTM 模型 (LSTM Model)**: 包含模型架構、訓練權重、超參數配置 (含特徵集 ID) 的深度學習模型物件
- **超參數試驗紀錄 (Hyperparameter Trial Log)**: 記錄每次試驗的參數組合 (時間窗口、層數、單元數、Dropout、學習率、批次大小、特徵集 ID)、訓練歷史、驗證指標的結構化資料
- **預測結果 (Prediction Result)**: 包含預測日期、預測漲跌幅區間、信心度、預測收盤價區間、實際收盤價 (如有) 的輸出資料

## 成功標準 *(必填)*

### 可衡量結果

- **SC-001**: 基準模型在驗證集上的分類準確度 **必須達到 (MUST achieve)** 至少 40% (高於隨機猜測的 20%)
- **SC-002**: 資料預處理與特徵工程流程 **必須能夠 (MUST be able to)** 在 10 分鐘內完成 10 年歷史資料的處理
- **SC-003**: 基準模型訓練 (使用 GPU) **必須能夠 (MUST be able to)** 在 2 小時內完成 100 個 epoch 的訓練
- **SC-004**: 超參數調整 **必須能夠 (MUST be able to)** 自動執行至少 50 次試驗並記錄所有結果
- **SC-005**: 最佳模型 (經過超參數調整後) 在驗證集上的分類準確度 **應該達到 (SHOULD achieve)** 至少 50%
- **SC-006**: 使用者指定日期後，系統 **必須能夠 (MUST be able to)** 在 10 秒內完成預測並返回結果
- **SC-007**: 訓練過程中的 GPU 記憶體使用率 **必須保持 (MUST remain)** 在 90% 以下以避免記憶體溢位
- **SC-008**: 系統 **必須能夠 (MUST be able to)** 處理完整的歷史資料集 (1998-2025，約 6,800 個交易日) 而不發生記憶體錯誤

## 假設與限制

### 假設

- 歷史股價資料來源為專案根目錄的 `19980601-20251111-converted.csv` 檔案
- 歷史股價資料已完成基本清理，無明顯異常值
- 法人籌碼資料與股價資料的日期範圍一致
- 訓練環境具備 NVIDIA GPU 與 CUDA 支援
- 使用者熟悉基本的機器學習概念與 Python 程式語言

### 限制

- 模型僅預測漲跌幅區間 (分類問題)，不直接預測精確的收盤價數值
- 預測結果基於歷史模式，無法預測突發事件 (如重大政策變動、國際市場崩盤) 的影響
- 超參數調整可能需要數小時至數天，取決於搜尋空間大小與運算資源
- 系統需要 WSL2 環境支援，無法直接在 Windows 原生環境下使用 GPU 訓練
