# Feature Specification: Enhanced Stock Price Prediction Visualization

**Feature Branch**: `002-enhanced-prediction-viz`
**Created**: 2025-11-16
**Status**: Draft
**Input**: User description: "開一個新的python檔案來寫以下的預測功能。套用目前的程式演算法來預測未來的股價漲跌,但除了目前可以看到的5類別漲跌幅區間,我還要把極度下跌和溫和下跌的機率加總,成為'看跌',把極度上漲和溫和上漲的機率加總,成為'看漲',並把這三類也視覺化呈現。此外,5分類的結果也要同步呈現,並且目前極度下跌和極度上漲的橫條圖沒有和其他的3個分類對齊,造成我不容易閱讀,這個部分要把每個分類的橫條圖起點對齊,更容易看出哪個類別機率最高。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - View Simplified 3-Category Prediction (Priority: P1)

作為股票分析師,我想要快速查看預測結果的簡化版本(看漲/震盪/看跌),以便快速做出投資決策而不需要分析5個詳細類別。

**Why this priority**: 這是核心價值主張,提供簡化的投資信號讓使用者快速判斷市場方向。大多數使用者主要關心「買入/持有/賣出」的簡單信號,而非詳細的漲跌幅區間。

**Independent Test**: 可以透過執行預測程式並驗證3分類聚合圖表正確顯示機率總和來獨立測試。此功能提供完整的投資決策價值,無需其他功能支援。

**Acceptance Scenarios**:

1. **Given** 已有訓練好的模型和歷史資料, **When** 執行預測程式並指定輸入日期, **Then** 系統顯示3分類預測結果,其中「看跌」機率 = 極度下跌機率 + 溫和下跌機率
2. **Given** 已有訓練好的模型和歷史資料, **When** 執行預測程式並指定輸入日期, **Then** 系統顯示3分類預測結果,其中「看漲」機率 = 極度上漲機率 + 溫和上漲機率
3. **Given** 已有訓練好的模型和歷史資料, **When** 執行預測程式並指定輸入日期, **Then** 系統顯示3分類預測結果,其中「震盪」機率保持不變(等於原始5分類中的區間震盪機率)
4. **Given** 3分類預測結果已計算完成, **When** 查看視覺化圖表, **Then** 可以清楚看到3個類別的橫條圖,每個類別標示機率百分比

---

### User Story 2 - View Aligned 5-Category Detail (Priority: P2)

作為進階分析師,我需要同時查看原始5分類詳細結果,並且所有類別的橫條圖起點對齊,以便精確比較各類別機率高低。

**Why this priority**: 提供詳細分析能力給需要深入研究的進階使用者。雖然重要,但簡化版本(P1)已能滿足大多數使用者需求。

**Independent Test**: 可以透過執行預測程式並驗證5分類圖表正確對齊(所有橫條從同一起點開始)來獨立測試。無需P1功能即可驗證此視覺化改善。

**Acceptance Scenarios**:

1. **Given** 已有訓練好的模型和歷史資料, **When** 執行預測程式, **Then** 系統顯示5分類詳細結果,包含極度下跌、溫和下跌、區間震盪、溫和上漲、極度上漲的機率
2. **Given** 5分類預測結果已計算完成, **When** 查看視覺化圖表, **Then** 所有5個類別的橫條圖從相同的起點(左側對齊)開始繪製
3. **Given** 5分類橫條圖已對齊, **When** 比較不同類別的機率, **Then** 可以快速識別出機率最高的類別,視覺判讀誤差降低

---

### User Story 3 - View Historical Data and Validation (Priority: P2)

作為分析師,我需要在預測結果中同時看到歷史資料的實際股價(如果預測日期已過),以及預測結果與實際結果的比對,以便評估模型準確度並建立信心。

**Why this priority**: 這是關鍵的驗證功能,讓使用者能評估預測可靠性。對於已發生的日期,能立即驗證預測準確度,這對建立使用者信任至關重要。此功能與視覺化改善同等重要。

**Independent Test**: 可以透過使用歷史日期執行預測並驗證系統正確顯示實際價格與預測比對結果來獨立測試。此功能獨立提供模型驗證價值。

**Acceptance Scenarios**:

1. **Given** 預測日期的實際資料存在於歷史資料中, **When** 執行預測, **Then** 系統顯示實際收盤價和實際漲跌幅
2. **Given** 預測日期的實際資料存在, **When** 查看預測結果, **Then** 系統顯示實際類別(基於實際漲跌幅計算的5分類和3分類)
3. **Given** 預測和實際結果都已計算, **When** 查看比對結果, **Then** 系統清楚標示預測是否正確(5分類預測 vs 實際類別)
4. **Given** 預測和實際結果都已計算, **When** 查看比對結果, **Then** 系統清楚標示3分類預測是否正確(看漲/震盪/看跌 vs 實際分類)
5. **Given** 預測日期的實際資料不存在(未來日期), **When** 執行預測, **Then** 系統僅顯示預測結果,並標註「待驗證」或「未來預測」

---

### User Story 4 - Dual-View Prediction Output (Priority: P3)

作為使用者,我希望在同一次執行中同時看到3分類和5分類兩種視圖,以便根據分析深度需求靈活切換關注點。

**Why this priority**: 這是使用者體驗優化,整合P1和P2的輸出。雖然便利,但技術上可以分別執行兩種視圖來達成。

**Independent Test**: 可以透過執行預測程式一次並驗證同時輸出兩種圖表來測試。此功能整合P1和P2,提供完整的使用者體驗。

**Acceptance Scenarios**:

1. **Given** 已有訓練好的模型和歷史資料, **When** 執行一次預測程式, **Then** 系統在同一輸出中顯示3分類聚合視圖和5分類詳細視圖
2. **Given** 雙視圖預測結果已顯示, **When** 查看輸出, **Then** 3分類和5分類的數據保持一致性(3分類的總和等於對應5分類的總和)
3. **Given** 雙視圖預測結果已顯示, **When** 儲存結果至檔案, **Then** 兩種視圖都完整儲存在輸出檔案中

---

### Edge Cases

- 當5分類中某個類別機率為0時,聚合後的3分類如何顯示?(應正確加總,即使其中一個為0)
- 當所有5分類機率相近時,3分類視圖是否仍能清楚區分?(應能正確顯示聚合後的機率差異)
- 當橫條圖機率值非常小(<1%)時,視覺化是否仍清晰可讀?(應設定最小顯示寬度或標註數值)
- 當使用者輸入的日期無法預測時(如資料不足),系統如何處理?(應顯示清楚的錯誤訊息,沿用現有錯誤處理機制)
- 批次預測多個日期時,是否每個日期都顯示雙視圖?(應為每個預測日期生成完整的雙視圖輸出)
- 當預測日期恰好在資料集邊界時(最新一筆資料的20個交易日後),實際資料如何處理?(應正確識別部分資料存在的情況)
- 當實際漲跌幅恰好在分類邊界上(如剛好+2.5%)時,如何判定正確性?(應使用與訓練時相同的邊界判定邏輯)
- 當預測正確但機率不高時(如預測看跌35%但實際確實下跌),如何呈現?(應標示預測正確,但同時顯示信心度較低)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須計算3分類聚合機率,其中「看跌」= 極度下跌機率 + 溫和下跌機率
- **FR-002**: 系統必須計算3分類聚合機率,其中「看漲」= 極度上漲機率 + 溫和上漲機率
- **FR-003**: 系統必須保留原始5分類機率,「震盪」類別保持不變(等於區間震盪機率)
- **FR-004**: 系統必須生成3分類橫條圖視覺化,顯示看跌、震盪、看漲三個類別的機率
- **FR-005**: 系統必須生成5分類橫條圖視覺化,顯示所有5個類別的機率
- **FR-006**: 系統必須確保5分類橫條圖的所有類別從相同起點(左側對齊)開始繪製
- **FR-007**: 系統必須在每個橫條上標示機率百分比數值,確保精確度可讀
- **FR-008**: 系統必須在同一次執行中輸出3分類和5分類兩種視圖
- **FR-009**: 系統必須驗證3分類聚合結果的一致性(看跌+震盪+看漲的總和應為100%)
- **FR-010**: 系統必須沿用現有的預測邏輯(模型載入、特徵工程、日期驗證等)
- **FR-011**: 使用者必須能透過命令列參數指定模型檔案、資料檔案、輸入日期等參數
- **FR-012**: 系統必須支援批次預測多個日期,每個日期生成獨立的雙視圖輸出
- **FR-013**: 系統必須支援將視覺化結果儲存至檔案(如PNG圖片或文字報告)
- **FR-014**: 系統必須在視覺化圖表中清楚標示預測日期和輸入日期
- **FR-015**: 系統必須使用適當的顏色編碼區分看跌(紅色系)、震盪(灰色系)、看漲(綠色系)
- **FR-016**: 系統必須檢查預測日期是否存在於歷史資料中,若存在則載入實際收盤價和漲跌幅
- **FR-017**: 系統必須根據實際漲跌幅計算實際的5分類類別和3分類類別
- **FR-018**: 系統必須在輸出中同時顯示預測類別和實際類別(若實際資料存在)
- **FR-019**: 系統必須比對預測類別與實際類別,並清楚標示5分類預測是否正確
- **FR-020**: 系統必須比對預測類別與實際類別,並清楚標示3分類預測是否正確
- **FR-021**: 系統必須在視覺化中以不同標記或顏色區分預測正確與預測錯誤的情況
- **FR-022**: 系統必須在預測結果中顯示信心度(預測類別的機率值)
- **FR-023**: 系統必須對未來日期(實際資料不存在)標註「待驗證」或「未來預測」

### Key Entities

- **3-Category Aggregated Prediction**: 聚合後的預測結果,包含看跌(Bearish)、震盪(Neutral)、看漲(Bullish)三個類別及其機率
- **5-Category Detailed Prediction**: 原始5分類預測結果,包含極度下跌、溫和下跌、區間震盪、溫和上漲、極度上漲及其機率
- **Actual Market Data**: 實際市場資料,包含實際收盤價、實際漲跌幅、實際5分類類別、實際3分類類別
- **Prediction Validation Result**: 預測驗證結果,包含預測是否正確(5分類和3分類分別判定)、預測信心度、實際vs預測的對比
- **Prediction Visualization**: 視覺化輸出,包含橫條圖、機率標籤、日期資訊、顏色編碼、正確性標記
- **Prediction Input**: 使用者輸入,包含模型檔案路徑、歷史資料路徑、輸入日期、特徵集、時間窗口參數

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者能在5秒內從3分類視圖判斷市場方向(看漲/看跌/震盪)
- **SC-002**: 5分類橫條圖對齊後,使用者識別最高機率類別的準確度提升至95%以上(相較於未對齊版本)
- **SC-003**: 3分類聚合機率的計算誤差為0(看跌+震盪+看漲總和必須精確等於100%)
- **SC-004**: 單次預測執行時間增加不超過30%(相較於原始預測程式,包含歷史驗證時間)
- **SC-005**: 視覺化圖表在1920x1080解析度螢幕上清晰可讀,所有文字和數值不重疊
- **SC-006**: 批次預測10個日期時,所有日期的雙視圖輸出格式一致且完整
- **SC-007**: 90%的使用者能在首次使用時正確理解3分類和5分類視圖的關係
- **SC-008**: 系統處理邊界情況(如極小機率值)時不產生視覺化錯誤或資料遺失
- **SC-009**: 當實際資料存在時,使用者能在3秒內判斷預測是否正確(透過清楚的正確/錯誤標記)
- **SC-010**: 實際類別計算的準確度為100%(與訓練時使用的分類邏輯完全一致)
- **SC-011**: 95%的使用者能正確理解預測信心度與預測準確性的關係

## Assumptions

- 現有的預測邏輯(模型載入、特徵工程、機率計算)已經過驗證且正確無誤
- 使用者已有訓練好的模型(.h5檔案)和對應的配置檔案
- 使用者已安裝必要的視覺化套件(matplotlib或類似工具)
- 預測結果的5分類機率總和已經標準化為100%
- 橫條圖視覺化適用於終端機文字輸出或圖形介面輸出
- 使用者熟悉現有的predict.py CLI介面和參數格式
- 3分類的命名(看漲/看跌/震盪)符合台灣股市分析師的慣用術語
- 歷史資料CSV檔案包含完整的日期和收盤價欄位
- 分類邊界定義與訓練時一致(極度下跌<-5%, 溫和下跌-5%~-2.5%, 震盪-2.5%~+2.5%, 溫和上漲+2.5%~+5%, 極度上漲>+5%)
- 預測日期的「20個交易日後」可能部分或完全不在歷史資料範圍內(正常情況)

## Out of Scope

- 修改現有的LSTM模型架構或訓練邏輯
- 新增其他聚合方式(如4分類或自訂聚合規則)
- 互動式視覺化介面(如網頁版dashboard)
- 即時串流預測功能
- 批量歷史回測分析(自動掃描所有歷史日期並計算整體準確率)
- 多模型比較視覺化
- 匯出為Excel或PDF格式
- 自動化交易信號生成
- 預測錯誤原因分析或診斷功能
- 基於驗證結果的模型自動調整或再訓練

## Dependencies

- 現有的`src/prediction/predictor.py`模組提供預測邏輯和5分類機率計算
- 現有的`src/cli/predict.py`提供命令列介面框架
- matplotlib或類似視覺化套件用於繪製橫條圖
- 現有的模型配置載入機制(`src/utils/model_config.py`)
- 現有的日誌系統(`src/utils/logger.py`)
